## 4. UI 关系展示（§0.8「以时间线和对象关系为主」）

方案给的链条 `业务模型差异 → Hypothesis → 偏锋验证意图 → Evidence → Finding → 回写模型/图 → 重新规划`：

- 各环节的**独立承载已存在**：biz-tab（差异）、graph-tab（意图/探索）、findings-tab（发现）、retests-tab（复测）；
- **串联缺失**：跨对象引用（diff_id→hypothesis_id→evidence→finding）此前既无数据也无 UI。数据面：TI-05 已建 hypotheses.causation_id/evidence_refs.hypothesis_id/finding_id 引用列；UI 面归工作台实施任务（见 §5）。
- §0.8 明确「不建议静态架构图」——现状 coverage-graph/graph 是动态任务数据图，符合口径，保留。

## 5. 实施拆分（后续任务，本批不实施）

工作台实施预计改动 >5 个文件（新 tab 组件 + api.ts + 类型 + 现有 page.tsx 集成），且依赖两个前置：

1. **TI-11 第二阶段**：`GET /api/tasks/{id}/intelligence|hypotheses|capability-runs|timeline` 的**生产方接线**（Provider 注入 + capability_executions/hypotheses 写入方），否则工作台展示空态（TI-11 第一阶段见 0.15.69）；
2. **事件闭环接线**（TI-06 派发器的生产方/消费方注册），「正在理解的问题/下一步计划」类活动流条目才有事件源。

拆分建议（每项一张卡、一版本）：
- **TI-08-a**：任务详情页新增「智能」tab（快照 + 能力调用列表 + AutoDecision 展示，只读）；
- **TI-08-b**：假设/差异/发现三对象互链的右侧详情面板（数据引用列已备）；
- **TI-08-c**：偏锋/建模启动入口的任务上下文显式化（选择已有任务 vs 新建）+ sandbox experiment 标记（若产品要放开无任务实验）。
