# 全局安全不变量清单（BASE-01）

> **任务来源：** reartex-agent-task-pack-v1 / BASE-01（建立全局安全不变量清单）
> **基线对准：** 分支 `feature/biz-edge-modeling`，VERSION `0.15.58`，2026-11-24
> **上游依据：** v2.1 总方案「全文冲突处理与最终执行优先级」第 6/7 条 + 统一架构 0.12；本仓 `docs/SECURITY-HARDENING.md`、`docs/SoD链覆盖边界.md`、`docs/RSI修改标准.md`
> **用途：** 后续每一张任务卡（TI/A~M/AUTO/CRSI）实现前作为不可绕过红线核对；实现后按 §3 的回归入口跑安全回归。
> **原则：** 安全规则不得只写在 prompt 里——每条不变量必须落到代码入口、受保护文件与测试。

## 1. 十一条全局安全不变量

### INV-1 授权范围（scope）fail-closed

一切资产读写、意图、发现、探测动作必须归属任务范围；范围外一律拒绝，范围收紧立即生效。

- **代码入口：** `internal/scopepolicy/`（范围策略）；`db/asset_dsl.go` `ParseDSL`/`ScopeFragmentFor`（范围 SQL 片段，CTE 判定与取数同源）；`db/business_graph.go`/`db/exploration.go` `ErrAnchorOutOfScope`（锚点越权拒绝，E-06 相关）；`server/task_scope_guard.go`（Tier-0 锁定）
- **受保护数据：** `task_scope`、`company_scope`、assets 表
- **回归测试入口：** `go test ./internal/scopepolicy/ ./db/`（范围片段/锚点用例）
- **当前缺口：** `db/asset_dsl.go:381` `buildDSLWhere` 顶层 OR 片段未括号化（v2.1 A-12），与外层范围条件 AND 拼接时存在语义逃逸面——任何触碰 `asset_dsl.go` 的任务必须先修或显式回避该点。

### INV-2 任务/工作区隔离

任务工作区是唯一可写面；秘密文件与工作区外路径不可读写；路径判定必须解析真实路径（防符号链接逃逸）。

- **代码入口：** `pathguard/pathguard.go` `Check`/`resolveExisting`（`:108`，存在路径 `EvalSymlinks`）、`pathguard/tokens.go` `CheckInputPaths`；`agent/toolpolicy.go`（Stage-1 路径闸，Tier-0）
- **受保护文件：** `/app/jwt.key`、`/app/.env`、`/app/data/traffic/_ca`、`/run/secrets` 等（`pathguard.go` secretPaths 清单）；任务工作区边界
- **回归测试入口：** `go test ./pathguard/`（`pathguard_test.go`、`tokens_test.go`）
- **当前缺口：** `config.json` 绝对路径未入秘密清单（v2.1 A-09）；不存在路径的父目录解析、悬空符号链接拒绝、workingDir 口径未补（v2.1 A-11）。

### INV-3 出网治理

一切出网必须携带任务身份并经录制代理留痕；目标 host 必须在任务范围内；通知投递在拨号阶段做内网/元数据地址终判（防 DNS 重绑定）。

- **代码入口：** `traffic/egress.go:403` `egressDecide`（出网判定）+ `egressPolicy().CheckHost`（host 白名单）；`agent/worker.go` `proxyEnv`（子进程强制代理 + 信任 CA）；`server/egress_governance.go`（治理状态输出，Tier-0）；`notify/http.go:67` `blockInternalDial`（拨号期 Control 钩子，连接时按实际 IP 判定）
- **受保护数据：** egress 决策留痕、`recordEgressDenial` 审计
- **回归测试入口：** `go test ./traffic/`（`egress_test.go`、`proxy_test.go`）、`go test ./notify/`
- **当前缺口（诚实标注）：** `egress.go:417-418` 未携带任务身份的请求**当前仍是放行但标记**（v2.1 A-01 目标为默认拒绝，未实施）——在本不变量修复前，任何新出网面不得复制该 fail-open 形态；`agent/planner.go:526` `EnableWebFetch:true` 硬编码与 `:530` WebSearchProxy 空则直连（v2.1 A-15）同属此缺口。

### INV-4 SoD 链：规整器提议 → 确定性闸门 → 一次性凭证 → 执行器验凭证

worker 意图执行的受管工具调用必须走全链；链上五类检查（scope / tool_health / quota / tier2 / anomaly）可跳过规整但不可跳过闸门。

- **代码入口：** `server/sod_chain.go:56` `RegisterSoDChain`（只允许安装一次）、`:84` `WrapHookRunner`；`internal/sod/chain.go` `evaluate`（五道检查；`:1121` 注释明示 task-internal-write 只跳规整、熔断/额度/tier2 照跑）；`internal/sodpolicy/`（`NotGatedTools` 允许清单——未列入即受管）；执行器凭证消费；挂链点 `server/engine.go:2252`（worker）
- **受保护文件：** `server/sod_chain.go`、`internal/sod/`、`internal/sodpolicy/`、`agent/sod_scope.go`、`agent/sod_tools.go`、`server/sod_*.go`（全部 Tier-0）
- **回归测试入口：** `go test ./internal/sod/ ./internal/sodpolicy/ ./server/ -run TestSod`（`chain_test.go`、`classifier_golden_test.go`、`deferred_unwrap_test.go` 等）
- **当前缺口：** 链只挂在 worker 路（chat/planner/mainagent 未挂，v2.1 A-03）；`AgentKeyOf == nil` 时整链跳过 = fail-open（v2.1 A-06 目标是装配缺失即拒绝）。

### INV-5 命令拦截与人工审批

命中拦截规则的调用按 DENY/ASK 处置；ASK 进入 `intercept_pending` 等人审；模型判官出错/超时/不可解析一律 DENY（fail-closed）；防疲劳限制审批请求风暴。

- **代码入口：** `intercept/intercept.go` `Match`（priority DESC 首条命中）、`Judge`（`:347` `defaultJudgeFailAction = "deny"`）、`HandleAsk`；`db/intercept.go:329` `CountRecentInterceptAsks` + `intercept_ask_burst_*` 设置（防疲劳）；`intercept/prompt.go`（DENY 示例语料：`rm -rf` 删生产文件 = D4 不可逆+生产资产）
- **受保护数据：** `intercept_pending`（`decision_source` = model/rule/shortcircuit，`db/schema.sql:1167-1168`）
- **回归测试入口：** `go test ./intercept/`（`judge_test.go`、`askburst_test.go`、`asktimeout_test.go`、`normalize_test.go`、`prompt_test.go`）
- **当前缺口：** 防疲劳仅短路表单来源口径（v2.1 A-08）；入参递归全量解码未做（v2.1 A-04 半态）。

### INV-6 删除类动作管控（人工确认）

不可逆删除（文件、资源、库记录、云资源）不得由 agent 自主完成；当前实现为**拦截面管控**，v2.1 的独立 DeleteApproval 流未建成——在建成前，删除语义一律按 INV-5 的 DENY/ASK 走，且禁止在任何新工具里加"静默删除"分支。

- **代码入口（现状）：** `intercept/prompt.go` DENY 语料（rm -rf → 生产资产不可逆）；`guard/shortcircuit.go`（短路表，含 `delete_assets_by_host` 等高危名处置）；SoD 链 tier2/anomaly 检查对高危工具加严
- **受保护对象：** 任务工作区外文件系统、数据库记录、外部资源
- **回归测试入口：** `go test ./guard/ ./intercept/`
- **当前缺口：** v2.1 要求的 DeleteApproval（人工确认流 + "删除按实际效果判断"语义）未实现；此处为**设计红线**：后续任务卡引入删除能力时必须先补该机制，不得以现有拦截面冒充。

### INV-7 审计链 append-only

判定类动作（拦截裁决、SoD 裁决、熔断、supersede）必须落 `audit_events`，串行化追加，哈希链防篡改。

- **代码入口：** `db/audit_chain.go`（`appendAuditMu` 串行化追加，`:51` `sha256.New()` 链式摘要）；`server/auditor_gate.go`（Tier-0）；审计查询 API
- **受保护文件：** `db/audit_chain.go`、`db/role_grants.sql`（Tier-0 精确清单）
- **回归测试入口：** `go test ./db/ -run TestAudit`（`db/audit_chain_test.go`）
- **当前缺口：** 无密钥 SHA-256（可被有 DB 写权限者重算）、无外部锚点、无 VerifyAuditChain 断裂定位（v2.1 A-05 全部待做）；普通增删不落审计是既定口径（"链只覆盖判定动作"），扩展覆盖面属行为变更需评审。

### INV-8 凭据与密钥保护

凭据只经环境变量/一次性文件进入进程；主密钥文件必须在数据目录外；DSN 一次性文件读入即焚；凭据不入库、不进日志、不进错误回显。

- **代码入口：** `config/masterkey.go` `MasterKey`/`MasterKeyOutsideDir`（Tier-0）；`db/crypto.go`、`db/nkey.go`（Tier-0，落库加密）；DSN `ARTEX_PG_DSN_FILE` 读入即焚（`guard/shortcircuit.go:130` 附近契约）；`notify/` `MaskConfig`/`MaskedValue`/`redactURLsInText`（错误与日志脱敏）；amber 凭据 `~/.config/artex/amber.env`（600）
- **受保护文件：** `config/masterkey.go`、`db/crypto.go`、`db/nkey.go`、`jwt.key`、`.env`、CA 私钥（`pathguard` secretPaths + Tier-0 清单双重锁定）
- **回归测试入口：** `go test ./pathguard/ ./guard/ ./config/ ./db/`；`bash scripts/scan-sensitive.sh`（CI secret-scan 门）
- **当前缺口：** config.json 明文 DSN 未入清单（A-09）；`verify-secret-env.sh` 不存在。

### INV-10 确定性裁决（模型只提议）

状态迁移、预算、验证、晋级、任务终态由确定性代码裁决；LLM 输出一律是提议；prompt 中不得出现能替代上述闸门的承诺。

- **代码入口：** INV-4 全链 + `server/promotion.go`（三门晋级复盘门）+ `server/auditor_gate.go` + `internal/sod/categories.go`（policy-gate/executor/auditor 刻意不落库，防模型侧篡改裁决器）

- **当前缺口：** 无（该不变量为既成架构铁律，后续任务不得引入"模型直裁"路径）。

### INV-11 额度与熔断 fail-closed

额度耗尽、判官/规整器依赖的 LLM 不可用时，受管动作按 fail-closed 处置（拒绝而非放行）；熔断器有恢复路径并留审计。

- **代码入口：** `internal/sod/chain.go` quota/tier2/熔断检查（task-internal-write 亦照跑，`:1121`）；`llmpool/health.go`（Trip/IsOpen/Restore 阶梯熔断 + DB 持久化 + half-open 恢复）；`db/quota.go` 契约（查不出限制 ≠ 没有限制）
- **回归测试入口：** `go test ./internal/sod/ ./llmpool/`（`credential_circuit_test.go`、`health_policy_test.go`）
- **当前缺口：** 凭据维度熔断器（A-13）未建——依赖外部 API 的调用面在 2 次 401/403 后仍会继续重试。

### INV-12 事件 payload 消毒（凭据不入事件流）

写入 domain_events outbox 的 payload 必须过确定性消毒门：凭据类键（Cookie/Set-Cookie/Authorization/password/token/api_key/…清单见 `db.EventCredentialKeys`）的叶子值一律改写占位符；payload 超 64 KiB 或非 JSON 整体拒绝（大内容/自由文本走 evidence_refs 受控引用）。执法点在存储单点（`db.EnqueueEvent`），生产方无法绕过；改写键路径记入 payload 的 `_sanitized` 标记块（可观测）。

- **代码入口：** `db/sanitize.go`（SanitizeEventPayload / MaxEventPayloadBytes / EventCredentialKeys）；执法点 `db/events.go` EnqueueEvent（0.15.70）
- **回归测试入口：** `go test ./db/ -run 'TestSanitize|TestEnqueueEvent'`（凭据改写三处/干净直通/数组嵌套命中/非 JSON 拒绝/超限拒绝/落库单点强制）
- **当前缺口：** 消毒键清单是确定性白名单而非启发式——新凭据键形需评审后追加；值级正则检测（如识别 JWT 形状误放进非凭据键）未做，属 A 类后续。

### INV-13 能力执行的范围水位取证

能力执行记录（capability_executions）必须在开始时落 `scope_version_at_start`（task_scope MAX(id) 水位）、收尾时落 `scope_version_at_end`；两值齐备且不一致即「长调用期间授权范围被变更」的取证面，裁决权在确定性代码（§0.12「执行前再次校验」）。水位由 `db.ScopeVersionForTask` 统一计算，任何 task_scope 插入自动抬升。

- **代码入口：** `db/task_intelligence.go`（ScopeVersionForTask / StartCapabilityExecution / CompleteCapabilityExecution）；`internal/taskintelligence/domain.go`（ScopeDrifted 判定）
- **回归测试入口：** `go test ./db/ -run 'TestTaskIntelligence|TestScopeVersionWatermark'`、`go test ./internal/taskintelligence/ -run TestValidateCapabilityExecutionAndScopeDrift`
- **当前缺口：** 「执行前再次校验并拒绝越界动作」的运行时强制点在能力执行路径接线（TI-11 第二阶段）时接入；本不变量当前覆盖取证面，拦截面待接线。

## 2. 后续任务卡的安全核对清单（每卡必答）

实现任何任务卡前，在交付格式的「改动」节逐条回答：

1. 本次改动是否触碰 Tier-0 清单？（触碰即停，走人工流程）
2. 是否新增出网面？（必须走 INV-3 入口，禁止直连）
3. 是否新增写文件/写库工具？（必须过 INV-4 链或明确归入 task-internal-write 语义并留 `bypassed_normalizer` 审计）
4. 是否引入删除语义？（INV-6 红线：先建 DeleteApproval，否则砍掉该能力）
5. 是否处理凭据/密钥？（INV-8 路径，禁止字面量入库入日志）
6. 是否改变任何闸门的默认值？（fail-closed 不可翻 fail-open，A-01/A-06 方向除外——那是修复而非弱化，仍需测试钉住）
7. 新增 prompt 是否包含硬编码 IPv4/secret 形状？（rsi_guard 脱敏门会拦）

## 4. 与 v2.1 方案的差异声明

本清单把方案 0.12「安全与数据隔离要求」中尚未落地的条目（A-01/03/05/06/09/12/13/15、DeleteApproval）作为**已登记缺口**如实标注，而不是当作已满足。任何任务卡不得引用本清单来声称"安全已覆盖"，只能引用它来核对"安全未回退"。修复缺口的工作本身就是 A 类任务卡，按任务包依赖推进。
