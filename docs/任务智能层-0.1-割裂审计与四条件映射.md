## 1. 四个孤岛的现状核对（0.1 原文逐条）

### 孤岛① 偏锋探索自成体系，结果不一定进入任务主链

**现状：部分改善，未闭合。**

- 已有：偏锋探索已任务化——`edge_cells`/`edge_runs` 落库并挂 `task_id`（`db/schema_edge2.sql`）；`server/edge_tools.go` 全家族工具（`edge_init_cells`/`edge_dispatch`/`edge_conclude`/`edge_switch` 等）带任务范围校验；`edge_consult`（`server/edge_tools.go:201`）允许 chat 侧咨询并留痕，但"候选假设被用户认可后再用 edge_run/edge_activate 升级"——即**进入主链仍靠人工升级动作**，无自动回写事件。
- 缺口：偏锋运行结论（confirmed/disproven/folded）停留在 edge_* 表，不产生领域事件驱动主 agent 重新规划（0.15.53 的 settle 回写只更新格点状态，不发事件）。

### 孤岛② 业务建模与偏锋假设、常规证据缺统一引用

**现状：存储面已就绪，引用面缺失。**

- 已有：`biz_layer_diffs`（`db/business_graph.go:137` `BizLayerDiff`，diff_type/severity/design_ref/behavior_ref）即方案 ModelDelta 的存储本体；`biz_model_versions` 提供可回滚快照版本。
- 缺口：`biz_layer_diffs` 行没有指向 hypothesis/evidence 的稳定外键关联；偏锋假设（edge_cells criterion/intents）也不引用模型版本——两边靠人对照。

### 孤岛③ 各模块局部上下文，跨模块人工搬运

**现状：属实。**

- 任务上下文分散在：范围（`task_scope` + `internal/scopepolicy`）、资产图（assets）、探索图（exploration_*）、业务图（biz_*）、事实（facts）、证据（traffic/evidence）、发现（findings）——没有统一快照聚合器（BASE-00 已核实无 `taskintelligence` 包）。
- 关联 ID 现状：**无 `correlation_id`/`causation_id`/`execution_id` 任何落库**（全库 grep 零命中）；任务身份仅有 `task_id`，chat 群绑会话经 `server/conversations.go:570` 注入 `RunInfo{TaskID, ExplorationID}`。
- **无 scope 版本快照**（scope_version 零命中）——长任务期间范围收紧后，旧上下文快照无法被检测为过期。

### 孤岛④ 前端独立功能卡，能力调用关系不可见

**现状：属实。**

- `web/src/app/(main)/function/` 下 10 张独立卡片：assets / business-graph / commands / findings / llm-records / miniprogram / peak-search / **pianfeng（偏锋）** / sync / tasks——各自独立入口，无"该能力在当前任务中何时被调用、输入输出去了哪里"的时间线视图。

## 2. 四条件落地映射（目标 → 现状 → 归属任务）

| 条件 | 现状 | 归属 |
|---|---|---|
| ① 同一任务身份（task_id/scope/tenant/execution_id/correlation_id） | task_id 全线具备；chat 群绑有 RunInfo 注入；**execution_id/correlation_id/causation_id 零落库；scope_version 无** | 身份字段随 TI-05 `CapabilityExecution` 统一落库；本仓无租户维度（单租户部署），tenant 按方案 0.12 口径暂不适用 |

| ③ 同一结果契约（Hypothesis/Fact/Evidence/ModelDelta/Finding，不留模块私有文本） | 领域对象存储已在（intents/facts/findings/biz_layer_diffs/edge_cells），但"能力调用记录"无统一载体 | 统一领域对象随 **TI-05** 落库；能力登记随 **TI-03**（本轮落地注册表本体） |
