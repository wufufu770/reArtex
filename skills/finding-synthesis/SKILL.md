# 多线索综合与定级

在**已授权**前提下，把探索图里散落的线索（facts / findings / traffic / 资产指纹）综合成**完整、可复现、按平台口径定级**的漏洞结论。本 skill 回答两个问题：**这些线索拼起来说明什么？它值几级？**

## 什么时候加载自己

- 单个 work 的结论是「现象 A」「现象 B」，规划者怀疑它们是同一条链；
- 评级拿不准（info 还是 low？medium 还是 high？）；
- 复核既有 finding：证据是否支撑所报级别、有没有组合升权被漏掉。

## 综合四步

### 1. 收全证据

- `graph_overview` / `node_detail` 把相关 fact/finding 的完整 evidence 拉出来（摘要不看细节会漏组合点）；
- `traffic_search`/`traffic_get` 核对每个关键结论的原始请求/响应——**只认落库流量与命令输出，不认转述**；
- `list_task_findings` 看已报结论，避免重复登记。

### 2. 拼链（组合升权对照表）

| 组合 | 升级形态 |
|---|---|
| 信息泄露（凭据/key） + 可达服务 | 认证绕过/接管 |
| XSS + CSRF / XSS + 权限接口 | 账户接管 |
| SSRF + 云元数据端点 | 云接管 |
| 文件上传 + 解析漏洞/路径可达 | webshell/RCE |
| IDOR + 批量遍历（ID 可枚举） | 大规模泄露 |
| 低危注入 + 二阶上下文（存库回显） | 存储型链 |
| 版本指纹 + 公开 exploit 可触发 | 可利用 1day（必须实际触发验证） |

拼链的标准：**每一环都有独立证据**，环与环之间有真实数据流（上一步的产出确实被下一步用了）。缺环就如实写缺在哪，报 fact 而非 finding。

### 3. 定级（平台口径，拿不准降一档）

- **critical**：可验证敏感数据外泄 / RCE / 数据库完全控制 / 认证绕过接管 / 支付金额篡改；
- **high**：可验证 SQLi 可读数据 / SSRF 达内网或云元数据 / IDOR 可读他人敏感数据 / 未授权后台 / 可执行文件上传；
- **medium**：有前置条件的利用（存储型 XSS 有场景 / 敏感操作 CSRF / CORS 泄露了具体数据）；
- **low**：需用户交互（反射 XSS） / 带凭据或利用链的未授权读取；
- **info**：纯信息泄露与暴露类（无凭据无链）、未证实候选面——**漏洞类别是 info_disclosure 且没拿到凭据或可继续利用的链，一律 info**。

定级自问三句：最坏后果是什么？达成最坏后果还需要哪些前置（都已在链内=按组合后定级；缺前置=降档）？不懂安全的开发者能看懂危害吗？

### 4. 落笔

- 综合出的新结论 → `report_finding`（summary 写明**完整链条**与每环证据位置；traffic_refs 按 proof/baseline 分角色绑定）；
- 对既有 finding 的定级修正走复核/更新面，不重复登记新条；
- 拼不成的链 → `record_fact`（inferred，写清缺环），交规划者补探测。

## 纪律

- **综合不是脑补**：每个组合断言都要能回答「证据在哪个节点/哪条流量」；答不上来的组合就是猜想，记 inferred。
- 降级原则优先：定级犹豫时写低一档并说明升级条件——错报 high 的代价大于漏报 low。
- 不为凑链重复探测已有流量覆盖的请求（先查 traffic）。
